Claude Managed Agents: Self-Hosted Sandboxes + Webhooks

Announced May 27 alongside the security-guidance plugin: self-hosted sandboxes keep Anthropic's orchestration in the cloud but move tool execution — code runs, filesystem writes, browser control, network egress — into infrastructure you configure. Supported providers today: Cloudflare, Daytona, Modal, Vercel, or your own AWS/GCP stack. Your security tooling, audit logging, and network policies apply; files and repos never leave your perimeter. Webhooks round out the release: session-start, session-end, and vault lifecycle events fire to any HTTP endpoint so you can trigger CI/CD, alerting, or downstream automation when an agent job completes. Together with the Dreaming (self-grading loop between sessions) and Outcomes (rubric-driven eval, +10pp task success on hard tasks) shipped at Code with Claude May 6, Managed Agents now covers the full lifecycle from deployment to improvement.

Context Mode (mksglu)

2.5k stars, Show HN. Claude Code's 200K-token context window disappears fast: Playwright MCP alone can eat 30%+ before you've typed a prompt. Context Mode fixes this by sandboxing tool output — raw data never enters the context window. The headline benchmark: 315 KB of MCP output becomes 5.4 KB, a 98% reduction. Works via PreToolUse/PostToolUse hooks that route output through a local sandbox (6 MCP tools: ctx_batch_execute, ctx_execute, ctx_index, ctx_search, ctx_fetch_and_index, ctx_execute_file), with meta-tools for summary and diff. Hook-capable installs get automatic setup from start.mjs; works with Claude Code, Gemini CLI, VS Code Copilot, Cursor, OpenCode, Codex, and 9 more. MIT.

claude-peers-mcp (louislva)

~1.6k stars. Solves an under-discussed problem: when you're running three Claude Code sessions in parallel (frontend, backend, migrations), they have no idea each other exist. claude-peers-mcp adds a local broker on :7899 (SQLite-backed) and an MCP server to each session. Any session can call discover_peers to find active instances by project and context, then send_message to pass instructions, diffs, or coordination signals — all over localhost, no cloud. The pattern unlocks real multi-session coordination without custom orchestration code: one session can hand off a spec to another, ask for a status, or request a review while both agents keep running their own workflows. MIT.

datasette-agent (Simon Willison)
