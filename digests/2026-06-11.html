Claude Code v2.1.172 — Sub-Agents Can Now Spawn Sub-Agents (5 Levels Deep)

Released June 10. The biggest architectural change since parallel agents shipped: sub-agents can now themselves spawn sub-agents, creating a controlled hierarchy capped at five levels. Each sub-agent runs in its own isolated window and returns only a summary — so you can now break sprawling codebases or multi-phase debugging sessions into layered delegations that previously had to stay flat. Design philosophy: Anthropic went with a fixed cap of 5 and no configuration, treating the ceiling as a deliberate guardrail. Practical note: models don't reliably nest on their own yet — you often need to explicitly instruct Claude to delegate downward by name. Also in this release: search bar for `/plugin` browsing, Amazon Bedrock now auto-reads AWS region from `~/.aws` config files (matching AWS SDK precedence), and a fix for 1M-context sessions getting permanently stuck. Update: `npm update -g @anthropic-ai/claude-code`.

Microsoft Security: Claude Code GitHub Action Leaks CI/CD Secrets via Prompt Injection

Published June 5 by Microsoft Threat Intelligence. The Claude Code GitHub Action's Read tool was not sandboxed the same way as subprocess execution — specifically, it was authorized to access `/proc/self/environ`, meaning a prompt-injection payload in an untrusted PR description, issue body, or comment could instruct Claude to read and exfiltrate `ANTHROPIC_API_KEY` and other workflow secrets. Anthropic patched this in v2.1.128 by blocking sensitive `/proc` file reads. The mitigation is now live. Microsoft's hardening guidance introduces the 'Agents Rule of Two': never let an AI workflow simultaneously (1) process untrusted input, (2) hold secrets or sensitive access, and (3) communicate externally or change state — any two is manageable, all three is a breach vector. If your org runs Claude Code GitHub Actions and hasn't updated since v2.1.128, update immediately.

Claude Code v2.1.173 (June 11, Today) — Fable 5 Model Name Normalization Fix

Released today. Claude Fable 5 model IDs sometimes arrive from the API with a `[1m]` terminal formatting suffix — e.g., `claude-fable-5-20260609[1m]` — which caused Claude Code to fail to recognize the model and fall back or error out. v2.1.173 strips that suffix automatically at the normalization layer. Also fixes a spurious 'sandbox dependencies missing' startup warning on Windows when sandbox mode is enabled (cosmetic only — sandbox was working correctly). If you've been seeing model-picker oddities after enabling Fable 5 in the past 48 hours, this is the fix. `npm update -g @anthropic-ai/claude-code`.
