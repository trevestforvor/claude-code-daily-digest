Claude Code v2.1.178 (June 15) — Tool Parameter Matching, Nested Skills, Auto-Mode Security Fix

Released June 15 with 22 changes. The headline feature: Tool(param:value) syntax in permission rules lets you match on a tool's input parameters (with * wildcard) — e.g., deny Agent(model:opus) to block Opus subagents specifically, or allow Bash(command:git*) to whitelist only git commands. Nested .claude/ support: skills in nested directories auto-load, name clashes become dir:name, and workflow saves target the closest .claude/. Auto-mode security fix: subagent spawns are now evaluated by the classifier before launch, closing a gap where blocked actions could be requested via subagent without review. Other fixes: OOM crash from stale WebSocket env vars, Chrome auth token account mismatch, compaction not honoring --fallback-model, vim undo merging, VSCode IME dismissal cancelling tasks.

Claude API: claude-sonnet-4-20250514 and claude-opus-4-20250514 Retired June 15

Two original Claude 4 release models were retired from the Claude API on June 15: claude-sonnet-4-20250514 and claude-opus-4-20250514 now return errors on all API calls. The practical migration: update to claude-sonnet-4-6 (claude-sonnet-4-6-20260620 or alias) and claude-opus-4-8. For teams with hardcoded model IDs in Agent SDK calls, GitHub Actions, or automation workflows — this is likely the cause of any 404/invalid model errors you're seeing today. Timing note: both retirements hit on the same day as the billing change reversal, so if your workflows broke today, check model IDs before billing.
