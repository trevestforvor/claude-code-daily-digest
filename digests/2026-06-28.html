claude-cognitive — Attention-Based Working Memory for Claude Code (HOT/WARM/COLD File Tiers, ~449 Stars)

claude-cognitive replaces flat file injection with a three-tier attention model: HOT files (>0.8 score) are injected in full, WARM (0.25–0.8) are injected as headers/signatures only, and COLD files are skipped entirely. Scores decay between sessions; multi-instance state sharing keeps separate Claude Code windows consistent on the same project. The practical effect is that context stays focused on files the session is actively editing rather than burning tokens on boilerplate that hasn't changed.

Statewright — State Machine Guardrails for Claude Code via MCP (5 Tools Visible per State; SWE-bench 2/10 → 10/10)

Statewright wraps Claude Code (and Codex, Cursor, Pi) in a declarative state machine via MCP: each state exposes only the tools valid for that step, so Claude sees 5 tools instead of a 30-tool menu. On a SWE-bench subset, local models jumped from 2/10 to 10/10 correct once tool choices were constrained by state. The Rust engine is Apache 2.0; the MCP gateway is FSL-1.1-ALv2 (converts to Apache 2.0 in 2029). 402 stars, debuted on Show HN this week.

Claude Code Trusted Devices for Remote Control — Team/Enterprise Admin Verification Gate (June 26)

Added to Claude Code on June 26: Team and Enterprise admins can now require device verification before any Remote Control session is allowed. Devices enroll during the sign-in flow (not ad-hoc), and the gate is off by default — orgs opt in via admin settings. The feature targets the session-hijacking surface identified by Mitiga Labs in April: a stolen token that passes auth is still blocked if it originates from an unverified device.
