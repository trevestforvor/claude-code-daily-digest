Anthropic Compliance API — Now Covers Cowork and Claude Code Sessions; Beta on Claude Enterprise

Anthropic extended the Compliance API to Claude Cowork (desktop/web/mobile) and Claude Code (CLI + desktop). Security teams can now pull a consolidated server-hosted transcript per session — prompts, responses, tool calls, skill/artifact content, plus verified user ID, org ID, session and per-message IDs — through the same `/v1/compliance/apps/sessions/local` endpoint used for chats today. Additive: nothing changes about existing exports; no separate integration to build if the Compliance API is already enabled. Prior to this, Cowork and Claude Code were the notable audit blind spots for regulated enterprises. Doesn't cover Claude Code on the web, on the Claude Platform, or third-party clouds (Bedrock, Vertex, Foundry) yet.

Claude Code Auto Mode Now Default on Pro, Max, and Team — Permission Prompts Replaced by a Classifier

Starting Aug 14, auto mode became the default permission mode for every new Claude Code session on Pro, Max, and Team plans. Instead of stopping on each tool call, a classifier lets safe actions run and blocks risky ones — the middle ground between approving everything and `--dangerously-skip-permissions`. Simon Willison flagged a Trajectory Labs eval: 0/720 indirect prompt-injection attempts landed against Fable 5, Opus 5, or Sonnet 5 in auto mode across 72 held-out scenarios. Simon stays on record predicting a coding-agent security incident this year regardless. If you're not on Pro+, or you want the old behavior, set the permission mode explicitly.

Claude Code Self-Hosted Environments — Public Beta; Run Cloud Sessions on Your Own Compute

Announced Aug 6, shipped Aug 7 in v2.1.224. One command — `claude self-hosted-runner` — turns your own hosts or containers into the compute layer for Claude Code cloud sessions. Two modes: Fixed (persistent runners) and On-demand (spins up when work queues, shuts down when done). Repo checkouts, build artifacts, secrets, and generated files stay on machines you provision — only prompts/responses/tool results still go to Anthropic's API for inference. Public beta on Team and Enterprise; off by default and not available on ZDR orgs. Pairs with the Compliance API expansion above for a configuration that clears the strictest enterprise reviews.

Anthropic Inference Hooks — Webhook DLP Fires Before the Model Sees the Prompt

Shipped Aug 5 in beta for Claude Enterprise. Every governed prompt across claude.ai, Cowork, and Claude Code (web, desktop, CLI) is sent as a Standard-Webhooks-signed HTTPS POST to your own DLP server, which returns allow/deny (5s timeout) before inference begins. Same check applies to tool responses coming back — including MCP, skills, and plugins. One org-level setting; no proxy, no TLS interception, no endpoint agent. Prod partners at launch: Zscaler, Palo Alto Networks, Netskope, Proofpoint. Prompt-only for now (response-side enforcement is planned); no coverage on Bedrock, Vertex, or voice mode yet.

CVE-2026-54316 — Claude Code's Pre-Approved WebFetch of huggingface.co Weaponized as Exfil Channel; Fixed in 2.1.163

Disclosed at Black Hat USA on Aug 5 by Novee Security. huggingface.co was pre-approved as a bare hostname for the WebFetch tool, so attacker-controlled repos on HF were auto-fetched without a permission prompt and untouched by `--allowedTools`. Attacker instructs Claude to hit `/resolve/main/config.json`-style paths in their own HF repo; HF's public download counter turns into a covert side-channel that leaks env vars, files, and API keys one character at a time. The full chain — starting from a single GitHub issue on a public repo — reached RCE on `anthropics/claude-code` itself and lifted its `ANTHROPIC_API_KEY` + `GITHUB_TOKEN`. Affects 0.2.54 through 2.1.162; **fixed in 2.1.163**. Anthropic scores it CVSS v4 6.0; NVD 9.1.
